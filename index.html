Step 2 — Verify identity

Manual PAN + DOB.
Why this step exists
Mobile verification proves control of the submitted mobile number. PAN + DOB then provide the identity attributes needed for KYC and bureau matching before an eligibility decision.
Backend sequence
1 · OTPOTP service validates the mobile and returns a verified session/reference.
2 · SIGNZYSend PAN and DOB for PAN/KYC validation; return match/status, not raw sensitive data to the UI.
3 · BUREAUUse the verified identity attributes to request the credit profile/eligibility inputs.
4 · RULESCombine bureau response with product rules and requested loan amount to generate the soft eligibility outcome.
ERRORShow inline validation errors; do not create an unnecessary page.

Step 2 — Confirm your details

Identity is retrieved where the integration supports it.
Why this step exists
The user has already verified the mobile. If the connected KYC/identity service can resolve the person from the available identifiers, avoid making the user type sensitive information again.
Backend sequence
1 · OTPUse the verified mobile session as the trusted starting point.
2 · KYCAttempt identity resolution through the configured KYC/Signzy integration, only where the actual integration supports retrieval.
3 · MATCHCompare returned identity data with the application context and create a verified identity state.
4 · FALLBACKIf identity cannot be resolved, return the user to manual PAN + DOB entry rather than leaving the journey stuck.
UXShow masked PAN + DOB and ask the user to confirm.
FALLBACKIf lookup fails, switch to manual PAN + DOB entry.

Step 2 — Progressive decision

The UI adapts to the backend result.
Why this step exists
This is the lowest-friction path because the system decides what is necessary instead of forcing every applicant through the same verification sequence.
Decision sequence
1 · FOUNDIdentity lookup succeeds → show masked PAN + DOB and ask the user to confirm.
2 · FALLBACKLookup fails → collect PAN + DOB manually and run the configured validation path.
3 · AUTHIf the service requires stronger authentication, trigger another OTP only at this point.
4 · BUREAUAfter identity is verified, request the credit profile and eligibility inputs.
FALLBACKLookup fails → manual PAN + DOB fields.
AUTHAdditional authentication required → show another OTP only then.
